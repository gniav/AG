# Стратегия коммитов

Для значительного функционального блока 30–50 коммитов, примерно 40, — ориентир, а не квота. Каждый коммит должен представлять самостоятельное полезное изменение. Реализуй и проверяй этап, затем создавай локальный коммит в процессе работы, если это разрешено для задачи; продолжай до завершения задачи. Не создавай пустые, фиктивные или избыточные коммиты и не реализуй всё заранее ради искусственного дробления истории. По возможности сохраняй работоспособность проекта после каждого коммита.

Используй Conventional Commits с типами feat, fix, refactor, test, docs или chore. Используй существующие Git user.name и user.email, не меняй авторство или даты, не добавляй ненужные служебные подписи, упоминания инструментов и автоматические Co-Authored-By. Не отправляй git push без отдельного разрешения. Явное указание пользователя не коммитить имеет приоритет; настройку инструкций саму по себе не коммить.
